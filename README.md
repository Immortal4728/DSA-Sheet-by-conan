## How this is structured

Each section is split into patterns, not just problem lists. Every pattern tells you what the technique is, when to use it, what the common mistakes are, and which problems demonstrate it best.

Problems have one canonical home. If a problem touches two topics, it lives in the more important one and is referenced from the other — it's never duplicated.

The question count per pattern is intentional. Some patterns have 2 problems, some have 8. It's based on how much variety actually exists in interviews, not on hitting an arbitrary number.

---

## How to use it

Open a section. Read the pattern file first — not the problem. Understand what problem structure triggers that pattern and why the technique works. Then open LeetCode in a blank editor and solve it without looking at any hints.

If you can't solve it, that's fine. Read the approach, close it, and solve it again from scratch the next day. The goal is to get to a point where you can look at a problem you've never seen and know within 2 minutes what pattern it belongs to.

Once you're done with a section, mix problems from it with problems from previous sections and solve them without knowing which pattern to use. That's the real test.

---

## What this is not

This is not a competitive programming sheet. USACO and Codeforces-style problems are out of scope. This is built specifically for product company SDE-1 interviews — Amazon, Google, Flipkart, Microsoft, and similar.

There are no filler problems. If a problem is here, it's here because it teaches something that the previous problems didn't.
