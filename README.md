## 🧭 How the Roadmap Works

```
Concept  →  Pattern  →  Representative Problems  →  Independent Solving
   ↓
Pattern Recognition  →  Optimization  →  Unfamiliar Variations  →  Interview Execution
```

Not this:
> Watch tutorial → copy solution → memorize → move on

This:
> Understand → Solve → Struggle → Recognize → Optimize → Explain → Transfer

Each section is built around **patterns**, not arbitrary problem lists. Understand the pattern, then solve. The problems exist to demonstrate the pattern — not to be memorized.

---

## 🧠 Philosophy

| Principle | Meaning |
|---|---|
| Pattern First | Learn reusable problem-solving structures |
| Blank Editor | Attempt problems without solution dependency |
| Canonical Ownership | Every problem has one home — no duplication |
| Depth Over Volume | No artificial question-count inflation |
| Transfer | Recognize patterns in unfamiliar problems |
| Complexity Awareness | Understand why an approach is fast or slow |
| Interview Focus | Prioritize practical SDE-1 reasoning |

> **Don't memorize solutions. Learn to recognize and reproduce the reasoning.**

## 🛠️ How to Use

1. Follow the syllabus in order.
2. Read the pattern file before solving any problem in that pattern.
3. Solve from a blank editor — no hints, no looking at solutions first.
4. Analyze time and space complexity for every approach.
5. Revisit problems until the pattern transfers to unfamiliar variations.
